# 把「領取塔羅」講清楚

## 為什麼

Tarot 明確告訴使用者「抽一支籤，就能再玩一次塔羅」，所以 Tarot 來的人本來就是來換獎勵的。
可是 Tarot 來、抽了籤的 537 人裡，只有 232 人點回 Tarot（發出 236 份獎勵）。agent 不是原因
（最後去向 96% 是 AI 解讀）。領取入口藏在解讀捲動區最底下，字是「去塔羅自己提問」，看起來是
推薦，不像領獎；抽籤前也沒人告訴他「看完解籤才能領」。

## 做什麼

**誰是獎勵版**：這個分頁從 Tarot 承諾獎勵的連結進來（`tarot-outro` / `tarot-locked` /
`tarot-other`，記在 sessionStorage，`tarot-share` 不算），這支籤是這次造訪抽的（`drawnHere`），
且解讀已經攤開。其餘的人畫面完全不變。

**解讀頁**：獎勵版的 Tarot 按鈕搬出 `.sheet-scroll`，放在「分享／追問／再求一籤」上面，翻到背面
就看得到；朱紅木札，字是「領取你的一次塔羅 →」。它是這一面唯一的朱紅木札，分享那顆降成一般木札。
點過一次（新分頁已開）改成「回到塔羅 →」；同一支籤的碼不變，不會領兩次。

**「解籤」底下一行小字**：原本想換抽籤前那一行，但籤筒閒置時已經不放常駐提示（使用者先前要求拿掉），
換不到。改放在籤紙正面「解籤」按鈕底下 —— 領獎的第一步就是按它：「看完解籤，就能回塔羅再玩一次」。
只有獎勵版看得到；是一行字，不是新框（invariant 7）。

**量測**：Reading health 加一張卡「看完後點回 Tarot」= `tarot:opened` ÷ `reading:shown-*`
（只用有 shown 計數的日子）。不新增計數。

## 不變

Tarot 獎勵的判定、兌換碼、`/api/tarot-claims` 都不動。無新框（invariant 7）：只是文字和一塊木札
換位置。新文案五張表都補，英文無連字號。

## 測試

- `promisesTarotReward(source)`：三個承諾來源為真，`tarot-share` 與其他為假
- 瀏覽器裡：從 Tarot 連結進來，同一分頁抽第一支籤之後仍記得（測試不能 import `src/app/`，在瀏覽器驗）
- 本地 `?vessel=printer&utm_source=tarot&utm_content=locked`：抽籤、「解籤」底下的小字、解籤、領取木札位置與字、
  點過後變「回到塔羅」；不帶 utm 時畫面照舊
