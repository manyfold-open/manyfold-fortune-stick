# 籤筒 v3：攪籤取代搖籤（設計）

日期：2026-09-22　分支：`feat/3d-cylinder-rebuild`　範圍：只在本機做，好了再上線。

## 為什麼改

使用者試過 v2（拖曳甩筒子、籤掉到地上），覺得顯示方式不好。v3 的方向：

- 籤筒**固定不動**，按住筒裡的籤拖動就是在攪；
- 攪夠了**自己決定何時放手**，放手就有一支自己升上來；
- 外觀照參考圖（奶油色日系籤筒）：更可愛、更寬更胖、籤更多；
- 螢幕空間大，籤筒在畫面上要更大。

## 不能動的規則（AGENTS.md）

- **抽到第幾籤由伺服器決定**（`drawStickNo`），攪籤動畫只演出那支，不影響結果。
  號碼在「攪夠了」那一刻就向伺服器要，寫進 `readings`，之後不會重抽。
- 升起那支顯示的號碼 = `sheet.stick.no`，沿用現在 `dr.chosen = sheet.stick.no - 1` 的來源。
- 可測的數學一律放 `src/shared/cylinder/`，不 import three、不碰 DOM。

## 互動流程

1. **還沒寫問題**：籤照樣可以攪（手感），但不累積進度（沿用 `armed`）。
2. **按住**：整塊畫布都是握把，滑鼠和手指一樣。筒子本身完全不動，最多保留極輕微的呼吸。
3. **攪**：手繞圈拖，籤束跟著手的方向在筒裡旋轉、互相推擠，籤頭晃動，有竹籤沙沙聲。
   進度條依攪動量增加；手越快累積越快，停著不動就不長。
4. **攪夠了**：進度條滿，提示「可以放手了」，同時呼叫 `onShake` 向伺服器抽籤。
   之後繼續攪多久都行，結果不變。
5. **放手**
   - 沒攪夠：什麼都不抽，籤慢慢停下歸位，提示「再攪一會兒」。
   - 攪夠了、伺服器已回應：籤束停下，抽中的那支自己慢慢升起，升到幾乎整支離開筒口，轉正面對鏡頭。
   - 攪夠了、伺服器還沒回應：籤束繼續輕輕翻動，回應到了才升起。
   - 抽籤失敗：照現在的 fault 顯示，可以重新攪。
6. **抽出（2026-09-23 修訂：要像手把籤拿起來，不是籤自己跑出來）**。不畫手，只靠籤的動作表現：

   | 時間 | 籤 | 鏡頭 |
   |---|---|---|
   | 0～0.3 秒 | **抓住**：其他籤停下，中籤那支先往上輕提再頓一下（捏住籤頭的阻力） | 不動 |
   | 0.3～1.3 秒 | **抽出**：邊往上拉邊轉成直立，貼著筒口滑出；旁邊幾支被帶得跳一下再落回 | 不動 |
   | 1.3～2.0 秒 | **拿到面前**：離開筒口再往上提、移到筒子正上方、轉正面對鏡頭，換上「第 N 籤」 | 跟著籤頭高度一路推近（2026-09-23 修訂，見下） |
   | 2.0～4.0 秒 | **拿著看**：輕微晃動 | 約 2.4 秒到位，框住籤頭到號碼 |
   | 之後 | 淡出（`HANDOFF_FADE_MS`），交給籤紙頁 | |

   - 抽出的路徑是算出來的：籤貼著筒口那一點滑動、先轉直再上升，任何時刻筒口以下那一段都在內壁以內。
   - **沒有自由落體、不落地**：`eject.ts`、落地俯拍 `revealShot`、筒子淡出 `revealCupFade` 全部移除。
     籤被拿到筒子正上方，筒子落在近拍畫面之外，擋不到號碼。
   - 鏡頭**跟著籤頭的高度**推近（`pullCamera`），不用彈簧也不用固定時間表 —— 固定時間表的版本實測籤頭會先衝出畫面頂端。籤直立，鏡頭一直正立，不會翻轉。
7. **減少動畫**：`prefs.reducedMotion` 開著時，升起與鏡頭推近直接跳到結束狀態。

## 外觀（照參考圖）

1. **籤呈扇形散開**，像一把花束：外圈的籤明顯往外傾，籤頭是大圓盤。
   傾斜以筒口為支點（籤靠在筒口上，下端往內），要保證任何一支都不穿出筒壁。
2. **筒身更寬更胖、圓角更圓潤**。依既有鐵律：`TUBE_H` 不動，靠 `TUBE_ASPECT` 加粗；
   `CUP_N` 往圓的方向調。
3. **狗更大**：有腮紅、抱著梅花，占杯身下半部一大塊。
4. **光線暖、柔、對比低**，像奶油色塑膠。
5. **籤的數量**：60～80 支，實際數量由填充率算（≥ 30%，胖筒子要更多支才不會稀疏）。
   **筒裡的籤不印號碼**，只有籤頭「籤」、「上上籤 / GOOD LUCK」與小圖案（梅花、雲、
   富士山、鳥居、達摩輪流）。抽中那支升起時才換成印有「第 N 籤」的版本。
   - 附帶好處：籤身貼圖只要 5 種圖案變體，不用再做一格一支的 atlas
     （現在 36×128 = 4608px 已經超過 WebGL 保證的 4096 上限，80 支會到 10240px）。
     號碼版只在揭曉時為那一支畫一張。
6. **畫布更大**：填滿首屏剩下的高度，但提示文字與進度條不能被擠到折線以下。

## 狀態機

`rest → stirring → ready → pulling → done`

- `rest → stirring`：按住且攪動強度超過門檻。
- `stirring → rest`：沒攪夠就放手。
- `stirring → ready`：攪動功達門檻（呼叫 `onShake`）。
- `ready → pulling`：已放手 **且** `chosen >= 0`（伺服器已回應）。兩個條件缺一個就留在 `ready`。
- `pulling → done`：時間軸跑完（約 4 秒），淡出交棒。

## 測試

全部是 `src/shared/cylinder/` 的純函式，vitest 直接測：

- **stir**：沒 `armed` 不累積；手停著不長；強度取自手速且有取樣間隔下限（沿用 12ms 的教訓）；
  達門檻只觸發一次；放手後旋轉會衰減到停。
- **pull**：任何時刻筒口以下那段都在內壁以內、不穿筒底；抽出後高度只升不降；拿著時直立、在筒心正上方、正面朝鏡頭；減少動畫一步到終點；壞輸入不出 NaN。
- **geometry**：任何一支籤都不穿出筒壁（扇形傾斜後逐支檢查筒口與筒底兩端）；填充率 ≥ 30%；
  籤數落在 60～80。
- **framing**：待機鏡頭在各種長寬比下整支籤筒（含扇形展開的籤頭）四邊留一成白，**含透視**
  （上一輪量到下緣只剩 2%，就是沒算透視）；揭曉近拍框住籤頭到號碼、四邊留白。
- 測試一律**獨立重算**，不抄模組的答案。

瀏覽器實測：本機 dev server 實攪一次，量像素確認待機與揭曉構圖，桌機與手機長寬比各一次。
