# 拿籤到看籤：改成一口氣、不頓（計畫）

日期：2026-09-23　分支：`feat/3d-cylinder-rebuild`　狀態：**計畫已提給使用者，等確認後開做**

使用者回饋：「拿出來到看籤的過程要優化，現在不是很絲滑」。

## 量到的問題（`pull.ts` + `framing.ts` 的 `pullCamera`，aspect 1.7）

| 時間 | 籤頭速度 (u/s) | 鏡頭推近 (u/s) | 問題 |
|---|---|---|---|
| 0～300 ms | +1.3 → **−1.3** | 0 | 抓住那一下先往上、又**往回掉**（`TUG * sin(π·u)`） |
| 800 ms | **20**（峰值） | **43**（峰值） | 半秒內衝上 7 單位；鏡頭綁在籤頭高度上，同時從 25 猛衝到 10 |
| **1300 ms** | **0** | **0** | PULL 段 ease-out 收到 0、PRESENT 段 ease-in 從 0 起步 → **完全停住再起步** |
| 1650 ms | 4.2 | 8.9 | 第二個小衝刺；號碼貼圖在這一格**硬切換** |
| 2000～4000 ms | 0 | 0 | 拿著看整整 2 秒**完全靜止**，接著淡出 |

量法：寫一個臨時 vitest，對 `pullPose(bundleSlot(PULL_INDEX), t)` 的籤頭高度與
`pullCamera(t, 1.7).camZ` 做中央差分（±8ms），每 50ms 印一行。

根因三個：**分段動畫**（每段各自 ease-in-out，接縫處速度歸零）、**鏡頭跟得太死**
（進度直接等於籤頭高度進度）、**號碼硬切換**。

## 計畫

1. **籤一口氣拿起來**：整段只有一個速度峰，中間不歸零、不往回掉。
   - 抓住只往上提，直接接上抽出（速度連續）。
   - 轉直、移到筒心、轉正面**疊在上升過程裡**，不各自排一段。
   - 峰值籤頭速度 ≤ 6 u/s；放手後約 2.2 秒拿到面前（總長大致不變）。
2. **鏡頭先抬頭、再推近**：拆成兩個通道 —— 視線高度（lookY/camY）跟著籤走，保證籤頭在
   畫面裡；推近（camZ）慢一拍、較長時間完成，峰值 ≤ 15 u/s。
3. **號碼淡入**：轉正途中約 250 ms 從透明到清楚（例如籤身正面疊一片印號碼的薄面，動它的 opacity）。
4. **拿著看不凍住**：輕晃 + 微微往上浮，鏡頭極慢地繼續推近；淡出在還在動的時候開始。
5. **放手那一刻**：其他籤約 0.5 秒慢慢歇下來（現在 `m.y *= exp(-6·dt)` 約 0.17 秒就停）。

## 驗收（先寫測試，看它紅，再改）

- 從起步到停穩，籤頭速度**單峰**、中間不低於某個比例、**不為負**。
- 籤頭峰值 ≤ 6 u/s；鏡頭推近峰值 ≤ 15 u/s；每 16ms 的速度變化量有上限。
- 籤頭全程在畫面裡（`cylinder-framing.test.ts` 既有測試）；不穿筒壁、不穿鄰籤（既有測試）。
- `pullCues` 的鈴聲仍與號碼出現同一格（改成淡入後，以淡入開始那一格為準）。
- 號碼淡入的 opacity 單調遞增、歷時 ≥ 200 ms。
- 瀏覽器逐格截圖（0.3 / 0.8 / 1.3 / 1.7 / 2.2 / 3.0 秒），對照上表確認。
